# 网文小说 AI 生成系统 — 完整创作流程设计

> **核心原则**：网文的本质是读者留存，而非文学表达。爽点密度、钩子强度、升级节奏，决定一切。

---

## 总览：八层创作漏斗

```
┌─────────────────────────────────────────────────────────────┐
│  第一层  类型定位 & 爽点设计          ← 决定读者是谁        │
│  第二层  世界观 & 力量体系            ← 决定成长坐标        │
│  第三层  人物设计                     ← 决定情感钩子        │
│  第四层  主线骨架                     ← 决定大方向          │
│  第五层  分卷规划                     ← 决定节奏密度        │
│  第六层  章节细纲                     ← 决定留存率          │
│  第七层  逐章写作                     ← 决定体验质量        │
│  第八层  一致性校验                   ← 决定可信度          │
└─────────────────────────────────────────────────────────────┘
         用户输入越往上越多，AI 接管越往下越多
```

## 第一层：类型定位 & 爽点设计

### 1.1 类型选择

网文类型直接决定读者群体、语言风格、爽点类型。必须在第一步确定。

| 大类 | 子类 | 核心读者诉求 |
|------|------|------------|
| 玄幻 | 洪荒流、异世界、东方玄幻 | 境界突破、打怪升级、系统面板 |
| 修仙 | 凡人流、道侣流、宗门流 | 长生追求、宗门争霸、仙路艰辛 |
| 都市 | 都市重生、隐世高手、商战 | 逆袭打脸、财富积累、高手低调 |
| 穿越 | 穿越古代、穿越异界、穿书 | 知晓剧情优势、改变命运、降维打击 |
| 系统 | 全职业系统、签到系统、直播系统 | 随机奖励快感、面板成长、任务驱动 |
| 末世 | 丧尸末世、异能觉醒、星际 | 生存压力、强者逻辑、人性考验 |
| 无限流 | 副本流、游戏流、诡秘流 | 解谜快感、规则博弈、死亡压迫 |
| 历史 | 权谋、种田、军事 | 布局感、历史改写、势力博弈 |

### 1.2 核心爽点设计（最重要）

**爽点是网文的灵魂。一本书只能有一个主爽点，可以有1-2个副爽点。**

#### 主爽点类型

```
A. 逆袭打脸型
   触发条件：主角被人看不起 / 被嘲讽 / 被欺压
   爽点释放：主角实力碾压对方，对方嘴硬到认怂全程
   代表作：《斗破苍穹》《万古第一神》
   关键设计：打脸要有铺垫，对方要足够嚣张，主角碾压要足够彻底

B. 升级爽型
   触发条件：获得资源/战斗/机缘，境界突破
   爽点释放：突破后实力大幅跃升，解决之前解决不了的问题
   代表作：《凡人修仙传》《一念永恒》
   关键设计：每次突破要有意义，不能为升级而升级

C. 系统面板型
   触发条件：完成任务/达成成就/击杀怪物
   爽点释放：获得奖励，面板数值上涨，解锁新技能
   代表作：《全职法师》《我的师兄实在太稳健了》
   关键设计：奖励要出乎意料但合理，任务要有趣不无聊

D. 装逼收徒型
   触发条件：主角低调，对方不识泰山，主角被迫亮身份
   爽点释放：对方反应从轻视→震惊→崇拜，越夸张越爽
   代表作：《万族之劫》《遮天》
   关键设计：低调要合理，揭露时机要精准，对方反应要到位

E. 复仇型
   触发条件：主角有深仇大恨，一步步接近仇人
   爽点释放：仇人从嚣张到绝望，最终被主角亲手解决
   代表作：《校花的贴身高手》《修罗武神》
   关键设计：仇恨动机要充分，复仇路要曲折，最终报仇要酣畅

F. 种田积累型
   触发条件：主角通过经营/研究/积累慢慢壮大
   爽点释放：势力壮大，俯视曾经的强敌，资源源源不断
   代表作：《大国重工》《工业霸主》
   关键设计：积累过程要有趣，每个里程碑要有满足感
```

#### 副爽点（可叠加）
- **感情线爽点**：心仪对象倒贴、误会解开、青梅竹马
- **义气爽点**：兄弟情深，共患难，有人为主角两肋插刀
- **揭秘爽点**：身世之谜、阴谋真相、世界规则背后的秘密

### 1.3 读者期待管理

不同爽点类型的读者对更新节奏的忍耐度不同：

| 爽点类型 | 爽点间隔容忍 | 铺垫接受度 |
|---------|------------|----------|
| 逆袭打脸 | 5章以内必须有一次 | 低，铺垫不能太长 |
| 升级爽 | 10章以内一次突破 | 中，过程要有趣 |
| 系统面板 | 3章以内一次奖励 | 低，节奏要快 |
| 装逼收徒 | 8章以内揭露一次 | 中 |
| 复仇 | 20章可以一次小复仇 | 高，读者有耐心 |
| 种田积累 | 无硬性要求 | 高 |

### 1.4 爽点工程化：5 阶段释放公式

**每种爽点都有工业级的 5 阶段释放路径，AI 必须严格遵守而非随意发挥。**

#### 逆袭打脸 5 阶段
| 阶段 | 内容 | 要点 |
|------|------|------|
| ①铺垫 | 对方出言不逊/轻视主角，旁观者或暗笑或不敢出声 | 被轻视越深，打脸越爽 |
| ②蓄力 | 主角沉默应对或低调反击，让对方继续嚣张 | 越嚣张越好 |
| ③反转 | 主角一击即中，展露真实实力，对方表情凝固 | 反转要干脆 |
| ④涟漪 | 旁观者震惊→议论→传扬，打脸效果被放大 | **旁观者反应是爽感放大器** |
| ⑤收尾 | 对方跪地/沉默/逃走，主角淡然离场 | 不做多余解释 |

- 频率：每 3 章 1 次小打脸，卷高潮 1 次大打脸
- 强度曲线：小打脸 2-3 分 → 中打脸 5-6 分 → 卷高潮 9-10 分
- 禁忌：不能打完脸还留情面；不能自谦"我只是运气好"；不能跳过旁观者反应

#### 升级爽 5 阶段
| 阶段 | 内容 |
|------|------|
| ①困境 | 被强敌压制或遭遇瓶颈，现有实力明显不够 |
| ②绝望 | 苦苦支撑，读者觉得这次真的要输了 |
| ③契机 | 灵感闪现/危机触发顿悟/金手指启动 |
| ④突破 | 渡劫/蜕变过程（要有仪式感+感官化描写——光芒/震动/天象） |
| ⑤碾压 | 以新境界实力逆转局面，打出之前不可能的攻击 |

- 频率：每 5 章 1 次小突破，卷高潮 1 次大突破
- 禁忌：不能无缘无故突破；不能"打坐三天就突破了"；突破后必须有战力对比

#### 其他爽点公式（简表）

| 爽点类型 | 核心 5 阶段 | 小爽点频率 | 大爽点频率 |
|---------|------------|----------|----------|
| 系统面板 | 触发→展示→惊喜→应用→优越 | 每 2-3 章 | 每卷 1 次系统进化 |
| 装逼收徒 | 伪装→轻视→露一手→全面揭露→追随 | 每 4 章 | 卷高潮完整揭露 |
| 复仇 | 仇恨积累→接近→突破障碍→复仇过程→清算 | 每卷 1 次打击 | 终卷最终复仇 |
| 种田积累 | 规划→执行→里程碑→超预期→格局升级 | 每 3 章成果展示 | 卷高潮格局质变 |

### 1.5 钩子类型库

**每章结尾必须有钩子。以下 7 种钩子类型可交替使用：**

| 类型 | 描述 | 示例 |
|------|------|------|
| 关键中断 | 最紧张时切断叙述 | "他猛地回头，看到的不是敌人——而是……" |
| 半截揭秘 | 惊人信息只说一半 | "原来所有人都错了。他不是什么废物——他是当年那个……" |
| 威胁升级 | 更大威胁出现 | "远方天际，一道比刚才那人强十倍的气息正在逼近。" |
| 信任动摇 | 极细微的背叛暗示 | "她转身离开时，手微不可察地颤了一下。只有他注意到了。" |
| 谜题加深 | 解答一个问题，引出更大谜团 | "但这一切，为什么和他梦中看到的一模一样？" |
| 力量预兆 | 暗示即将突破/觉醒 | "丹田中那颗沉寂了三年的种子，在这一刻，发出了第一缕光。" |
| 倒计时压力 | 设置明确时间限制 | "还有三天。三天后，他要么突破，要么——死。" |

### 1.6 章节节奏模板

**每章有 5 种节奏类型，不同类型的段落风格和禁忌完全不同：**

| 节奏类型 | 描述 | 节奏走向 | 段落风格 | 禁忌 |
|---------|------|---------|---------|------|
| action | 战斗/冲突章 | 快→快→极快 | 短段落 80-120 字，对话密集 | 禁止长段环境描写和内心独白 |
| buildup | 铺垫章 | 慢→中→快 | 中等段落 100-180 字，信息递增 | 全章不能平淡，最后 20% 必须加速 |
| revelation | 揭秘章 | 中→停顿→极快 | 揭秘前中等节奏，揭秘时短句冲击 | 真相不能一口气全说完 |
| aftermath | 缓冲章 | 慢→慢→中 | 较长段落 120-200 字，角色互动 | 必须在缓冲中埋入新线索 |
| turning_point | 转折章 | 中→停顿→爆发→余波 | 转折前正常，转折时极短段落 | 转折不能突兀，前面必须有铺垫 |

## 第二层：世界观 & 力量体系

### 2.1 力量体系设计

**力量体系是网文的坐标系，读者必须随时知道主角在哪里、离目标多远。**

#### 设计原则
1. **等级必须清晰**：读者一眼能看懂现在处于什么层次
2. **上限要模糊**：让读者感觉永远有更高处
3. **相邻等级差要悬殊**：跨级战斗才有压迫感和爽感
4. **突破要有代价**：资源/天赋/机缘，不能白给

#### 典型力量体系结构（以修仙为例）
```
炼体期（1-9层）      ← 主角开局，普通人的上限
  ↓
练气期（1-9层）      ← 真正踏入修仙
  ↓
筑基期              ← 分水岭，很多人一辈子到不了
  ↓
金丹期              ← 一方势力的支柱
  ↓
元婴期              ← 国家级强者
  ↓
化神期              ← 传说级人物
  ↓
渡劫期              ← 接近仙界
  ↓
大乘期              ← 即将飞升
  ↓
[仙界/更高维度]      ← 下一阶段的未知目标
```

#### 力量体系必须回答的问题
- 每个等级的典型战力表现是什么？（能劈山？能毁城？）
- 突破需要什么条件？（丹药/顿悟/功法/资源）
- 主角现在是什么境界？本书结束是什么境界？
- 主要反派什么境界？（要比主角高2-3个大境界）
- 境界差距多大开始碾压？（跨1小境界？跨1大境界？）

### 2.2 世界地图设计

```
[主角起点]  →  [第一个更大的舞台]  →  [更大的世界]  →  [终极舞台]
     ↑                ↑                    ↑               ↑
  小山村/         一国之内/            一大陆/           三千世界/
  破宗门           一宗门               诸天万界          仙魔神界
```

**每卷的舞台要比上一卷大，让读者感觉主角在不断向上突破。**

### 2.3 势力格局

```
势力地图（示例）：
┌───────────────────────────────────────┐
│  终极反派势力（全书大BOSS所在）          │
│  ├── 中期反派势力（2-3卷的障碍）        │
│  │   ├── 近期反派势力（1卷的障碍）      │
│  │   │   └── 主角当前所在势力         │
│  ├── 中立势力（可争取的资源）           │
│  └── 潜在盟友势力（后期联合）           │
└───────────────────────────────────────┘
```

### 2.4 核心资源体系

读者需要知道：**什么东西有价值，主角怎么获取，怎么消耗**

- 修炼资源：灵石/灵丹/功法秘籍的稀缺逻辑
- 机缘体系：遗迹/传承/天才地宝
- 经济体系（如有）：货币单位、物价参考

### 2.5 世界深度维度（让世界有灵魂）

**好的世界不只有力量体系，还有文化、哲学、历史。这些维度让世界可信，也为角色行为提供更深的驱动力。**

| 维度 | 说明 | 设计要求 |
|------|------|---------|
| 哲学内核 | 世界运行的底层哲学/思想 | 如"强者为尊"还是"众生平等"？这决定角色冲突的深层动机 |
| 文化体系 | 信仰、知识、传统 | 不同地区的文化差异可以制造误会和冲突 |
| 社会结构 | 阶层、权力运行逻辑 | 主角突破的不只是境界，还有社会阶层 |
| 历史纪元 | 3-5 个关键历史事件 | 历史事件是伏笔的天然容器（"上古大战"可以埋很多秘密） |
| 禁区/秘境 | 危险区域（进入条件+风险收益） | 主角成长的关键节点，也是节奏调剂的好工具 |
| 地理-境界绑定 | 每个区域推荐的境界范围 | "金丹期以下不可进入北域"——自然的等级门槛 |

## 第三层：人物设计

### 3.1 主角设计

#### 起点设计（低谷起点是网文标配）
```
理想主角起点公式：
  [身份低微 / 被人看不起的理由]
  +
  [隐藏的逆天天赋 / 独特金手指]
  +
  [明确的初始动机]
  =
  读者的代入感 + 对后续爽点的期待
```

**常见起点设定：**
- 灵根废材，实则隐藏顶级灵根
- 记忆失去，实则前世强者转世
- 被家族放弃，实则觉醒稀有血脉
- 普通现代人，意外获得系统/功法
- 被人陷害跌落谷底，卧薪尝胆

#### 金手指设计（主角的核心外挂）
```
金手指类型：
  系统类：签到系统/任务系统/合成系统/面板系统
  功法类：上古禁术/逆天功法/绝世传承
  空间类：储物空间/时间加速/世界戒
  血脉类：神兽血脉/上古传承/魔神体质
  知识类：前世记忆/未来预知/全知系统
```

**金手指设计原则：**
1. 要有规则限制，不能无限使用（否则无张力）
2. 要有成长空间（随主角等级解锁新功能）
3. 要与主爽点深度绑定（打脸型→快速升级；种田型→资源加速）
4. 不能解决所有问题（要留给读者担忧的空间）

#### 主角性格与爽点的匹配

| 主爽点 | 匹配性格 | 说话风格 | 禁忌性格 |
|------|---------|---------|---------|
| 逆袭打脸 | 自尊心强、睚眦必报 | 冷淡克制、出手才说话 | 懦弱、反复原谅 |
| 升级爽 | 勤奋执着、有野心 | 干脆利落、目标导向 | 随波逐流 |
| 装逼收徒 | 低调、内敛、有格局 | 惜字如金、出口成章 | 炫耀、浮躁 |
| 复仇 | 隐忍、冷静、有谋略 | 表面平和、实则算计 | 冲动莽撞 |

### 3.2 反派梯队设计

**网文反派必须是梯队结构，不能一开始就见大BOSS。**

```
反派梯队（从近到远）：

  第1卷小反派（直接接触，被主角第1卷解决）
       ↓ 背后有人
  第2-3卷中反派（某势力头目，需要成长才能对付）
       ↓ 背后有人
  第4-6卷大反派（势力领袖/某界强者）
       ↓ 背后有人
  终极大BOSS（贯穿全书，最后揭晓）
```

**每个反派设计要素：**
- 为什么要对付主角？（动机要充分，不能只是坏）
- 有什么实力？（比主角当时高多少？）
- 有什么弱点？（主角最终如何破局）
- 败亡时的反应？（越绝望越嚣张越好看）

### 3.3 感情线规划

```
感情线节奏（以一女主为例）：

  初遇（1-5章）：     相遇，留下印象，可能有误会
  拉锯期（中期）：    若即若离，误会加深，互相试探
  破冰（某个节点）：   一件大事让两人关系突破
  确认（约1/2处）：   心意相通，但外部阻力出现
  分离/考验（后期）：  危机让两人分离，读者揪心
  团圆（接近结局）：   克服一切，在一起
```

**感情线禁忌：**
- 主角全程舔狗，女主高冷毫无反应（读者会弃书）
- 女主比主角强太多（影响主角爽感）
- 三角恋拖太久不解决（读者会烦）
- 感情线抢占主线节奏（感情是调味料，不是主菜）

### 3.4 关键配角功能分工

| 配角类型 | 功能 | 设计要点 |
|---------|------|---------|
| 损友/兄弟 | 提供情绪价值，陪主角成长 | 要有自己的小故事，不能只是工具人 |
| 师父/长辈 | 传授知识，关键时刻出手 | 强大但有局限，最终让主角超越 |
| 商人/管家 | 解决后勤，提供资源 | 忠心耿耿，能力出众 |
| 神秘角色 | 制造悬念，关键情报来源 | 身份逐渐揭开，读者有猜测快感 |
| 炮灰反派 | 给主角打脸机会 | 必须足够嚣张，失败要有尊严 |

### 3.5 角色 Agent 化模型（核心设计理念）

**每个角色都是一个自主决策的 Agent，而不是作者的提线木偶。角色的行为应该能从其"灵魂数据"推导出来。**

#### 角色 6 层结构

```
┌───────────────────────────────────────┐
│  灵魂层（core_beliefs）               │ ← 几乎不变，变了就是重大转折
│  核心信念/价值观/底线                  │    例："绝不背叛同伴"
├───────────────────────────────────────┤
│  性格层（personality_traits）          │ ← 缓慢变化
│  行为模式/说话方式/习惯               │    例："沉默寡言，出手才说话"
├───────────────────────────────────────┤
│  状态层（power_level/location/alive） │ ← 每章可能变化
│  境界/位置/体力/情绪                  │
├───────────────────────────────────────┤
│  记忆层（known_facts）                │ ← 只增不减（除非特殊设定）
│  这个角色知道什么/经历过什么           │    用于信息差追踪
├───────────────────────────────────────┤
│  关系层（relationships）              │ ← 随事件变化
│  对其他角色的态度和信任度              │
├───────────────────────────────────────┤
│  目标层（goal_stack）                 │ ← 目标会冲突、会变
│  当前目标 / 长期目标                  │    例：[复仇, 变强, 保护师妹]
└───────────────────────────────────────┘
```

#### 行为禁忌设计

**每个主要角色必须有 2-3 条"绝不会做的事"。这是一致性校验的核心依据。**

```
示例：
  陈峰（主角）：绝不背叛师门 | 绝不伤害无辜 | 绝不在弱者面前炫耀
  李婉（感情线）：绝不使用黑暗法术 | 绝不出卖朋友
  张天罡（反派）：绝不对女人出手 | 绝不食言（即使对敌人）
```

如果剧情需要角色违反禁忌，**必须有充分的铺垫和转折理由**，且违反后角色必须有心理反应。

#### 典型台词示例

**每个角色设计时必须给出 2-3 句典型台词，用于写作时保持声音一致性：**

```
陈峰："多说无益。"（沉默型）
李婉："你又不听劝。"（关心但无奈）
张天罡："弱者不配知道答案。"（傲慢但有逻辑）
```

#### 反派深度设计（三维度）

| 维度 | 说明 | 例子 |
|------|------|------|
| 坚守底线 (heroic_code) | 反派也有不会做的事 | "绝不对女人出手" |
| 致命缺陷 (tragic_flaw) | 导致最终失败的性格缺陷 | "过度自信，从不认为自己会输" |
| 读者共情点 (sympathetic_element) | 让读者能理解甚至同情反派 | "其实是为了救被囚禁的妹妹" |

## 第四层：主线骨架

### 4.1 主角的终极目标

**一本网文必须有清晰的终极目标，读者要知道主角在为什么而战。**

```
目标类型：
  生存类：在末世/异界活下去
  复仇类：找到仇人，报仇雪恨
  称霸类：成为最强，俯视苍生
  守护类：保护某人/某个势力/某个世界
  追求类：长生/飞升/突破某个极限
  回归类：回到某个地方/找到某人
```

### 4.2 里程碑事件设计（全书5-8个）

```
里程碑事件 = 改变主角命运轨迹的大事件

示例（修仙类）：
  里程碑1：获得金手指/觉醒天赋，开始真正踏上修仙路
  里程碑2：加入某个大势力，获得修炼资源和庇护
  里程碑3：第一次以弱胜强，证明自己的价值
  里程碑4：势力被灭/亲人遇难，被迫走出舒适圈
  里程碑5：进入更大的舞台，接触到真正的强者
  里程碑6：揭开世界真相/主角身世之谜
  里程碑7：最终决战，主角站在世界之巅
```

### 4.3 伏笔与悬念网络

```
全书级悬念（贯穿全书）：
  - 主角的真实身世是什么？
  - 终极大BOSS的真实目的是什么？
  - 世界规则背后的秘密

章节级悬念（3-5章解决一个）：
  - 这次能不能突破？
  - 对方是敌是友？
  - 这个机缘有没有陷阱？
```

### 4.4 主题弧线设计

**好的网文不只是爽，还有"越往后越深"的主题层次。**

```
主题弧线三层递进：
  初期主题：如何变强？（生存/升级/打脸）
      ↓
  中期主题：为什么变强？（守护/责任/信念）
      ↓
  后期主题：强大之后怎么办？（孤独/抉择/传承）
```

- `thematic_arcs`：跨卷的主题弧线（如"正义与规则的冲突"贯穿全书）
- `core_dilemmas`：全书核心困境（如"救一人还是救万人"反复出现在不同尺度）

### 4.5 冲突升级管理

**冲突是小说的引擎。冲突必须持续升级，不能倒退。**

```
冲突升级阶梯：
  个人级（personal）：主角 vs 一个人的恩怨
      ↓
  组织级（organizational）：主角 vs 一个势力/家族
      ↓
  世界级（world）：主角 vs 世界规则/终极威胁
```

**规则**：
- 冲突不应无故降级（从"组织"退回"个人"需要充分的剧情理由）
- 每个冲突弧需要追踪：描述、当前级别、级别变化历史、状态（活跃/已解决/休眠）
- 多条冲突线可以并行，但主冲突级别应随卷数递增

### 4.6 里程碑的情感冲击维度

每个里程碑事件不只是"发生了什么"，还要标注：

| 维度 | 说明 | 示例 |
|------|------|------|
| 转折类型 | 反转/升级/牺牲/揭露/背叛 | "师父其实是卧底"→揭露+背叛 |
| 情感冲击 | 给读者和主角带来什么情绪冲击 | "信任崩塌→愤怒→理解→成长" |
| 格局影响 | 对主线格局的永久性改变 | "宗门被灭，主角被迫离开舒适圈" |

## 第五层：分卷规划（网文节奏核心）

### 5.1 卷的概念

**一卷 = 一个完整的故事弧 = 一套"压迫→成长→爽点爆发"循环**

每卷都要让读者感受到：
1. 本卷开始：遇到新威胁/新挑战（比上一卷大）
2. 本卷中段：被压着打，艰难成长，读者揪心
3. 本卷高潮：主角爆发，碾压对手，读者大爽
4. 本卷结尾：危机解除，顺带引出下一卷更大的威胁

### 5.2 标准卷结构模板

```
卷首（10%篇幅）：
  - 承接上一卷，主角现状
  - 新威胁/新目标出现
  - 本卷核心矛盾埋下

上升期（30%篇幅）：
  - 主角摸索，积累实力
  - 遇到本卷配角（盟友/敌人）
  - 小爽点每5章一次
  - 本卷反派开始施压

压迫期（30%篇幅）：
  - 主角遭遇最大困境
  - 被迫突破/觉醒/获得机缘
  - 读者揪心感最强的部分
  - 反派以为胜局已定

爽点爆发（20%篇幅）：
  - 主角反击，一路碾压
  - 打脸时机密集释放
  - 境界突破最终完成
  - 反派彻底败亡

收尾（10%篇幅）：
  - 危机彻底解决
  - 主角获得本卷奖励（资源/声望/感情进展）
  - 更大的威胁悄然出现（钩子）
```

### 5.3 卷与卷之间的节奏变化

```
张弛节奏：
  大卷（高强度）→ 过渡章节（低压力）→ 大卷（高强度）

过渡章节的功能：
  - 让读者喘口气
  - 推进感情线
  - 揭露小秘密/小伏笔
  - 主角整理收获，为下一卷做准备
  - 轻松向内容（读者需要调剂）
```

### 5.4 全书卷规划示例（5卷结构）

| 卷 | 舞台 | 主角境界 | 本卷反派 | 核心爽点 | 结尾钩子 |
|---|------|---------|---------|---------|---------|
| 第一卷 | 家族/小城 | 废材→炼气 | 家族欺压者 | 废材逆袭，震惊家族 | 发现外面世界更大 |
| 第二卷 | 宗门 | 炼气→筑基 | 同门竞争者 | 宗门比武碾压天才 | 被大势力盯上 |
| 第三卷 | 一国 | 筑基→金丹 | 国家级强者 | 金丹成就，名动一方 | 主角身世之谜出现 |
| 第四卷 | 大陆 | 金丹→元婴 | 元婴老怪 | 打破上限，震惊天下 | 终极大BOSS现身 |
| 第五卷 | 更大世界 | 元婴→更高 | 终极大BOSS | 彻底逆天，俯视众生 | 圆满结局 |

### 5.5 卷级伏笔管理

**伏笔是网文长篇连载的粘合剂。每卷必须"埋线"和"兑现"双向管理。**

```
卷规划必须包含两张清单：

  伏笔埋设清单（foreshadowing_seeds）：
    本卷新埋的线索/暗示/未解之谜
    标注：哪些是短期（1-2卷内兑现），哪些是长期（全书级）

  伏笔兑现清单（foreshadowing_payoffs）：
    本卷应该回收的前卷伏笔
    标注：兑现方式是否超出读者预期
```

**伏笔管理规则**：
- 短期伏笔（1-2卷内必须兑现）：读者记忆有限，拖太久就忘了
- 长期伏笔（全书级）：每隔2-3卷需要"提醒一下"，让读者保持好奇
- 禁止：埋了伏笔却忘记兑现（系统会追踪并报警）
- 禁止：兑现方式太平淡（"原来就是这样啊"——读者会失望）

### 5.6 主角情绪弧线

**每卷主角不只有境界成长，还有情绪变化。情绪弧线让角色有人味。**

```
每卷必须设定主角情绪弧线（protagonist_emotional_arc）：

  示例：
    第一卷：迷茫→不甘→觉醒→自信
    第二卷：自信→受挫→迷茫→突破后的从容
    第三卷：从容→背叛后的愤怒→复仇的执念→放下后的成长
```

**设计要点**：
- 情绪弧线不能单调上升（"越来越牛"不是情绪弧线）
- 每卷至少有一次情绪低谷（让读者心疼主角）
- 情绪转变需要事件触发（不能无缘无故变了心态）

### 5.7 道德困境设计

**让读者纠结的选择题，比简单的打怪升级更有深度。**

```
每卷可以设定一个道德困境（ethical_dilemma）：

  类型：
    A. 两害相权：救一人还是救百人？
    B. 手段与目的：用禁术能赢，但代价是什么？
    C. 立场冲突：师门命令与个人信念矛盾时怎么选？
    D. 灰色地带：对方不是纯粹的恶人，该不该下手？
```

**设计要点**：
- 困境没有标准答案（读者会讨论，增加互动性）
- 主角的选择要符合其性格和成长阶段
- 选择的后果要持续影响后续剧情（不能选完就忘了）

### 5.8 故事扩展（无限模式）

**网文连载可能需要超出原定卷数继续写。系统支持动态扩展而不崩坏。**

```
故事扩展的安全做法：
  1. 格局升级：进入新的更大世界（仙界→神界→更高维度）
  2. 新冲突线：已有世界中发现新的隐藏威胁
  3. 阵营翻转：曾经的盟友变成新的对手
  4. 时间跨度：时间跳跃后世界格局已变

  ✗ 危险做法（容易崩）：
    - 已死的反派复活
    - 主角无缘无故变弱（为了制造新张力）
    - 推翻已确立的世界规则
    - 无限堆叠境界（读者会疲劳）
```

## 第六层：章节细纲

### 6.1 章节单元结构

**每章 = 一个"钩子单元"，目标是让读者必须看下一章**

```
标准章节结构（2000-3000字/章）：

  ① 开头（200字）：兑现上章悬念，或新冲突直接出现
     ✗ 禁止：大段环境描写开头
     ✗ 禁止：复述上章情节
     ✓ 要做：第一段就有冲突/信息/动作

  ② 主体（1500字）：核心事件推进
     战斗章：铺垫实力对比→交手→转折→结果
     对话章：信息量要大，每句话推进情节
     修炼章：突破过程要有阻碍，成功要有代价

  ③ 结尾（300字）：制造新悬念，逼读者翻页
     钩子类型：
       - 意外出现型："就在此时，门外传来一声大笑……"
       - 揭秘型："你知道吗？那个人其实是……"
       - 危机型："主角突然发现，自己中了……"
       - 突破型："丹田之中，有什么东西，开始颤动……"
```

### 6.2 爽点分布图

```
爽点密度要求：

  每3-5章：  一个小爽点（小打脸/小突破/小揭秘）
  每10-15章：一个中爽点（正式突破境界/干掉重要反派）
  每卷高潮：  一个大爽点（碾压式反击/重大揭秘/里程碑突破）

  ✗ 禁止：连续10章无爽点（读者会弃书）
  ✗ 禁止：爽点密度太高，没有铺垫（读者会疲劳）
  ✓ 目标：让读者永远觉得"再看几章就会爽了"
```

### 6.3 章节类型与写法要点

#### 战斗章
```
写法要点：
  1. 实力对比先交代（读者要知道压力有多大）
  2. 主角不能轻松赢（至少要有一次陷入劣势）
  3. 胜利要有合理性（依靠金手指/机缘/智慧，而非纯运气）
  4. 失败要有意义（主角学到了什么/危险升级）
  5. 战斗节奏要快，动作描写简洁有力
  ✗ 禁止：主角无脑无伤取胜（没有压迫感）
  ✗ 禁止：战斗描写一直用同样的动词
```

#### 突破章
```
写法要点：
  1. 突破前必须有阻碍（感觉差一点点）
  2. 突破过程要有画面感（不只是"境界提升了"）
  3. 突破后立刻验证实力（打一个曾经打不过的人）
  4. 突破的代价/条件（消耗了什么资源/机缘）
  ✗ 禁止：无缘无故突破
  ✗ 禁止：突破后立刻遇到更强的直接碾压（影响爽感）
```

#### 对话章
```
写法要点：
  1. 每句对话要有信息量（推进情节/揭示性格/埋伏笔）
  2. 对话中要有动作/心理穿插（不能只有干巴巴的对话）
  3. 角色说话方式要有区分度（不能千人一面）
  4. 利用对话推进关系进展（拉近/疏远/误会）
  ✗ 禁止：大段解释性对话（角色解释给读者听）
  ✗ 禁止：所有角色说话风格一样
```

#### 揭秘章
```
写法要点：
  1. 揭秘前要有足够铺垫（读者有猜测快感）
  2. 揭秘内容要超出读者预期（不能太容易猜到）
  3. 揭秘后立刻引发新问题（悬念不能断）
  4. 揭秘的情感冲击（主角和读者都要有反应）
```

### 6.4 知识种子融入

**如果本书涉及特定学科（哲学、经济学、军事学等），每章可设定一个"知识种子"，自然融入剧情。**

```
知识种子设计原则：

  ✓ 通过角色行为展示，而非直接讲课
    正确："他按博弈论的逻辑，选择了最不像正常人的走法——合作。"
    错误："博弈论认为，在重复博弈中，合作是最优策略……"（读者翻书走人）

  ✓ 知识为剧情服务，而非剧情为知识服务
    正确：主角利用经济学知识预判了敌方的资源调配漏洞
    错误：为了展示经济学知识，强行安排一段贸易战

  ✓ 每章最多 1 个知识点，不能贪多
  ✗ 禁止：角色突然变身教授长篇大论
  ✗ 禁止：与剧情无关的知识展示
```

### 6.5 情绪节奏曲线自动校验

**系统会自动追踪每章的张力值，检测节奏问题。**

```
张力映射表：
  action（战斗/冲突）  → 张力 0.9
  turning_point（转折） → 张力 0.85
  revelation（揭秘）   → 张力 0.7
  buildup（铺垫）      → 张力 0.5
  aftermath（收束）     → 张力 0.3

自动检测规则：
  ⚠ 连续 3+ 章高张力（≥0.7）→ 警告"读者会疲劳，建议插入舒缓章节"
  ⚠ 连续 3+ 章低张力（≤0.4）→ 警告"读者可能流失，建议加入冲突"
  ⚠ 连续 3+ 章同类型          → 警告"节奏单调，建议变化章节类型"

理想节奏波形：
  高→中→低→中→高→爆发→低→中→高……
  ↑ 张弛有度，像心电图一样有节奏感
```

## 第七层：逐章写作

### 7.1 网文语言规范

**网文 ≠ 文学。网文的语言目标是：流畅、快节奏、情绪直接、无阅读障碍。**

```
网文语言原则：

  ✓ 句子短：多用短句，平均15字以内
  ✓ 动作多：多写动作，少写静态描写
  ✓ 对话推情节：对话占比30-40%
  ✓ 情绪直接：主角愤怒/爽快/震惊要让读者感同身受
  ✓ 节奏感强：张弛有序，战斗快，情感慢

  ✗ 禁止：大段堆砌的环境描写
  ✗ 禁止：过度文绉绉（除非设定需要）
  ✗ 禁止：拖沓的心理独白（超过200字）
  ✗ 禁止：解释太多（读者自己会脑补）
```

### 7.2 不同类型语感示例

#### 玄幻/修仙语感
```
✓ 正确示例：
"三道剑气斩出，将前方的山壁切开三道深沟。李逸收剑，眼神平静地看向对面那个面色发白的内门长老。
'这一剑，是还上次的债。'
长老的手微微颤抖，他没想到，眼前这个一个月前还是废物的少年，已经强到了这种地步。"

✗ 错误示例：
"李逸心中充满了愤怒，他感到自己体内有一股力量在涌动，这股力量让他感到无比的强大……"
```

#### 都市语感
```
✓ 正确示例：
"王总的笑容僵在脸上。他在商界摸爬滚打二十年，第一次感受到被人当小丑看待的滋味。
桌对面的年轻人将合同推回来，语气平淡得像在谈天气：'三个亿，我没兴趣。'"

✗ 错误示例：
"王总感到非常惊讶，他不敢相信眼前的年轻人会拒绝这个机会，要知道三个亿对普通人来说是多大的数目……"
```

### 7.3 主角视角保持

```
全书保持统一的主角视角基调：

  主角永远是最聪明的人（或者在成长为最聪明的路上）
  读者通过主角的眼睛看世界
  主角的判断要比周围人超前
  主角的情绪要让读者感同身受

  ✗ 禁止：主角明显比读者笨（会影响代入感）
  ✗ 禁止：主角轻易被愚弄（多次被同一类套路骗）
```

### 7.4 Writer 上下文架构

**写作不是盲写。Writer Agent 在写每一章时，会接收到丰富的上下文信息，确保前后连贯。**

```
Writer 看到的信息（按优先级排列）：

  ① 角色状态快照
     所有活跃角色的当前境界、位置、情绪、目标
     例："陈峰：筑基三层，在蓬莱秘境，情绪紧张"

  ② 信息差提示
     哪些信息"角色不知道但读者知道"（戏剧反讽）
     例："陈峰不知道李婉已被宗门驱逐"
     → Writer 可以利用这个制造张力

  ③ 角色禁忌提醒
     角色绝不会做的事
     例："陈峰：绝不背叛师门 | 绝不伤害无辜"
     → 如果剧情需要违反，必须有极充分的铺垫

  ④ 未兑现钩子
     前面埋了但还没回收的悬念
     例："第3章末暗示的神秘人身份（已悬挂5章）"
     → 悬挂太久的钩子需要兑现或推进

  ⑤ 近期节奏走势
     最近5章的张力曲线（可视化条形图）
     → 避免连续高张力或连续低张力

  ⑥ 消失角色提醒
     出场过但超过5章未出现的配角
     → 需要给读者交代或提及

  ⑦ 冲突格局
     当前活跃的冲突线及其级别
     → 保持冲突升级的一致性

  ⑧ 相关前情摘要
     与本章内容相关的历史章节摘要
     → 确保引用前文时不出错
```

### 7.5 写后自检流程

**Writer 写完一章后不直接提交，而是经过自检和修正。**

```
自检三步骤：

  1. 禁用词扫描
     检测禁用词出现次数：
       × "不禁" "顿时" "忍不住" "猛地" "深深地" "不由得"
       × "他心中感到" "她感到一阵" "内心充满了"
       × 连续三次相同动词
     → 发现问题后自动替换修正

  2. 字数校验
     检查中文字符数是否在目标字数 ±30% 范围内
     → 偏差过大会标记警告

  3. 修正策略
     只替换问题词汇/句式，保持其余内容不变
     替换后的表达必须自然、不生硬
     "不禁" → 删除或用动作替代
     内心描写 → 改为行为描写
     重复动词 → 用同义词替换
```

### 7.6 多学科深度写作

**本系统支持 20 种学科视角融入网文，但融入方式必须遵守"展示而非说教"原则。**

```
支持的学科方向（部分）：
  哲学、心理学、经济学、军事学、生物学、物理学、
  社会学、法学、医学、博弈论、政治学、人类学……

学科融入的三个层面：
  ① 世界观层：学科逻辑影响世界规则设计
     例：经济学 → 灵石通胀/通缩会影响宗门兴衰
  ② 角色层：角色的思维方式受学科影响
     例：心理学 → 主角能读懂对方的微表情和潜台词
  ③ 剧情层：关键转折依赖学科知识
     例：博弈论 → 主角用囚徒困境瓦解敌方联盟

  ✗ 禁止：角色突然掉书袋/长篇解释学科概念
  ✗ 禁止：学科知识与剧情脱节（为了展示而展示）
  ✓ 正确做法：读者看完后觉得"主角好聪明"而非"作者在炫耀"
```

## 第八层：一致性校验（自动化系统）

**一致性校验不再是手动清单，而是自动化的 16 类检测系统，支持多轮自动修正。**

### 8.1 16 类自动校验

| # | 校验类型 | 检查内容 | 严重度 |
|---|---------|---------|--------|
| 1 | 力量一致性 | 境界描述与设定是否冲突，越级表现是否合理 | 高 |
| 2 | 角色一致性 | 性格、说话风格是否与档案一致 | 高 |
| 3 | 设定一致性 | 地名、势力名、道具名前后是否一致 | 高 |
| 4 | 爽点落实 | 标注了爽点任务的章节是否真正写出来了 | 高 |
| 5 | 时间连贯性 | 章节间时间流动是否合理，有无"刚打完就恢复如初" | 中 |
| 6 | 地理位置 | 角色位置移动是否合理，有无"瞬移" | 中 |
| 7 | 因果逻辑 | 事件之间是否有因果关系 | 中 |
| 8 | 伏笔推进 | 前文伏笔在本章是否有推进或呼应 | 中 |
| 9 | 主题一致性 | 学科元素是否自然融入，有无突兀说教 | 中 |
| 10 | 时间线一致性 | 多角色视角下的时间是否对齐 | 中 |
| 11 | **信息差一致性** | 角色是否引用了自己不应该知道的信息 | 高 |
| 12 | **角色声音偏离** | 角色说话方式是否与典型台词风格一致 | 中 |
| 13 | **禁止项违反** | 角色是否做了违反其核心信念/底线的行为 | 高 |
| 14 | **钩子断裂** | 前章设置的悬念是否在本章或近期得到回应 | 中 |
| 15 | **角色消失** | 出场过的配角是否无故消失太久 | 低 |
| 16 | 钩子强度 | 结尾是否有效制造悬念（1-10 分评分） | 高 |

### 8.2 自动修正循环

**发现严重问题时，系统不只是报告，而是自动修正。**

```
自动修正触发条件（满足任一即触发）：
  - 力量一致性问题
  - 钩子强度 < 5 分
  - 严重的爽点落实问题
  - 禁止项违反

修正流程（最多 2 轮）：
  校验 → 发现严重问题 → 生成针对性修正 → 再次校验 → 通过/再修正
       └→ 无严重问题 → 直接通过

修正原则：
  - 只修有问题的部分，保持其余内容不变
  - 修正后文本必须与原文自然衔接
  - 保持原有的写作风格和节奏
  - 钩子太弱时只修改最后 1-2 段
```

### 8.3 质量评审（8 维度）

**除了一致性校验，系统还有独立的质量评审机制，从读者体验角度打分。**

| 维度 | 说明 | 评分标准 |
|------|------|---------|
| 总体分数 | 综合质量 | 1-10 |
| 爽点分数 | 爽点是否到位、释放是否充分 | 1-10 |
| 节奏分数 | 张弛是否有度、过渡是否流畅 | 1-10 |
| 沉浸感 | 读者是否能代入、画面感是否强 | 1-10 |
| 翻页欲 | 读者是否想看下一章 | 1-10 |
| 角色鲜活度 | 角色是否有辨识度 | 1-10 |
| 情感冲击 | 是否触动读者情感 | 1-10 |
| 逻辑自洽 | 事件因果是否合理 | 1-10 |

**评审结果处理**：
- 总分 ≥ 7：通过
- 总分 5-6：标记改进建议，不强制重写
- 总分 < 5：标记需要重写，提供具体改进方向

## 附录 A：实体记忆系统

**跨章节的角色/事件/伏笔记忆是长篇连贯性的核心保障。**

### A.1 角色状态 Agent 化追踪

每个角色在记忆系统中是一个完整的 Agent 实体：

```
角色状态数据结构：
  基础信息：name / role_type / current_power / location
  灵魂数据：core_beliefs / personality_traits / prohibitions
  记忆数据：known_facts（只增不减）
  目标栈：  goal_stack（当前目标 + 长期目标）
  声口数据：speech_examples（典型台词）
  生命周期：first_appearance / last_appearance / appearance_count / departure_status
```

### A.2 信息差管理（戏剧反讽）

```
信息差类型：
  A 知道但 B 不知道 → 可制造紧张/误会/戏剧性
  读者知道但所有角色不知道 → 悬念
  角色知道但读者不知道 → 揭秘素材

管理规则：
  - 每个信息差记录：谁知道、谁不知道、信息内容、创建章节
  - 信息差的"揭露"是重要的爽点素材
  - 信息差不应无限堆积（适时揭开或变得无关）
```

### A.3 时间线追踪

```
每章记录：
  - 故事内时间（in-story time）
  - 关键时间事件（"三天后比武"/"距离宗门大典还有七天"）
  - 多线交叉时的时间对齐校验
```

### A.4 上下文预算管理

**Writer 的上下文窗口有限，记忆系统按优先级截断注入。**

```
优先级排序（从高到低）：
  P1：角色状态快照（必须注入）
  P2：信息差提示（高价值）
  P3：角色禁忌提醒
  P4：未兑现钩子
  P5：节奏走势
  P6：消失角色提醒
  P7：冲突格局
  P8：相关前情摘要

默认上下文预算：2000 字符
超出预算时从低优先级开始截断
```

## 附录 B：完整系统架构

### B.1 八大 Agent 流水线

```
┌─────────────────────────────────────────────────────────────────────┐
│                        用户输入                                     │
│  类型 + 爽点 + 前提 + 字数 + 学科方向 + 质量模式                    │
└───────────────────────────────┬─────────────────────────────────────┘
                                ↓
┌───────────────────────────────┴─────────────────────────────────────┐
│  Agent 1: 世界构建师 (WorldBuilder)                                 │
│  输入：用户请求                                                     │
│  输出：力量体系 + 势力格局 + 世界规则 + 地理 + 历史 + 哲学内核       │
│  工具：无                                                           │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 2: 角色设计师 (CharacterDesigner)                            │
│  输入：用户请求 + 世界设定                                          │
│  输出：角色档案（含灵魂/禁忌/目标/典型台词）+ 反派梯队               │
│  工具：submit_characters                                            │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 3: 剧情规划师 (PlotPlanner)                                  │
│  输入：用户请求 + 世界 + 角色                                       │
│  输出：书名 + 里程碑 + 主题弧线 + 冲突框架 + 分卷规划               │
│  工具：submit_plot（含 extended thinking）                           │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 4: 章节大纲师 (ChapterOutliner) × N卷                       │
│  输入：卷规划 + 全局设定                                            │
│  输出：逐章细纲（开头/事件/钩子/爽点/节奏类型/知识种子）             │
│  工具：submit_chapter_outlines（含 extended thinking）               │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 5: 写作执行者 (Writer) × N章                                 │
│  输入：章节细纲 + 上章摘要 + 实体记忆上下文 + 节奏上下文             │
│  输出：流式章节正文 + 摘要                                          │
│  内置：写后禁用词自检 + 字数校验 + 断流续写                         │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 6: 一致性校验者 (ConsistencyChecker) × N章                   │
│  输入：章节正文 + 设定 + 实体记忆                                   │
│  输出：16 类校验 + 钩子评分 + 自动修正（最多 2 轮）                  │
│  工具：check_chapter_consistency                                    │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 7: 质量评审 (QualityCritic) × N章                            │
│  输入：章节细纲 + 章节正文                                          │
│  输出：8 维度评分 + 改进建议                                        │
├─────────────────────────────────────────────────────────────────────┤
│  Agent 8: 故事扩展 (PlotExtender)（按需）                           │
│  输入：已完成内容 + 设定                                            │
│  输出：新卷规划（格局升级/新冲突线）                                │
└─────────────────────────────────────────────────────────────────────┘
```

### B.2 辅助系统

| 系统 | 功能 | 说明 |
|------|------|------|
| **实体记忆** (EntityStore) | 跨章角色/伏笔/信息差/时间线追踪 | 每章后自动提取更新 |
| **节奏追踪** (RhythmTracker) | 情绪张力曲线监控 | 自动检测节奏异常 |
| **爽点系统** (PleasureSystem) | 5 阶段释放公式 + 钩子类型 | 指导 Writer 和 Outliner |
| **多学科系统** (Disciplines) | 20 学科 × Agent 交叉指导 | 每个 Agent 接收学科特定指令 |
| **工具注册表** (ToolRegistry) | 章节摘要搜索 + 设定查询 | Agent 可调用的参考工具 |
| **安全护栏** (Guardrails) | 输入过滤 + 输出扫描 | 防止不当内容 |
| **断点续写** (ResumableRunner) | 检查点保存 + 恢复 | 长篇生成中断后可恢复 |
| **可观测性** (Tracer) | LLM 调用追踪 + Token 统计 | 成本和性能监控 |
| **语义缓存** (SemanticCache) | LLM 请求结果缓存 | 避免重复调用 |
| **模型路由** (ModelRouter) | Per-Agent 模型分配 | 不同 Agent 用不同模型 |

### B.3 Human-in-the-Loop 交互

```
交互模式下，以下节点可暂停等待用户审批/修改：

  ① 世界观完成后 → 用户可修改世界设定
  ② 角色设计完成后 → 用户可调整角色
  ③ 剧情规划完成后 → 用户可调整卷规划和书名

审批选项：
  - approve：通过，继续
  - reject + feedback：驳回，附带修改意见，Agent 重新生成

超时处理：10 分钟未响应自动通过
```

## 核心理念总结

```
文学小说的目标：给读者一次深刻的精神体验
网文的目标：让读者今天看完还想明天继续看

文学小说的质量标准：意境、文笔、人物深度、主题深度
网文的质量标准：爽点密度、钩子强度、节奏控制、设定自洽

AI生成网文的最大敌人：
  × 节奏拖沓（没有爽点，读者等不及）
  × 设定不自洽（境界混乱，读者出戏）
  × 人物扁平（所有人说话一样，主角没有个性）
  × 钩子失效（章末没有吸引力，读者不翻下一章）
  × 爽点不到位（铺垫了半天，爽感很弱）
```
